# SolarTT-UI v0.1.0 — first stable single-node release

This release packages the accepted alpha.6 management panel and managed endpoint
for **Ubuntu 24.04, Linux x86_64, systemd**. The agent/panel runtime logic, managed
patch, dependency versions, configuration defaults and database schema are
unchanged. Version strings and release tooling change; the newly built package
and ELF digests have their own source/build identity.

## Included functionality

- Mobile and desktop administration through a private local panel.
- VPN users, separately issued device credentials, manual Android fields,
  compatible connection links/QR and TOML exports.
- Shared bidirectional payload quotas, expiry, calendar periods, manual resets,
  credential rotation and scoped revocation.
- Administrator-set issued-profile limits; lowering below the active issued
  count is refused. Copies of one credential are not separate physical devices.
- Encrypted credentials, audited exports, bounded audit/retry storage and
  guarded backup/restore. Existing committed traffic charges are preserved.
- The alpha.5 managed-download and alpha.6 active-stream listener fixes.
- Dependency/upstream maintenance workflows that propose reviewed changes;
  they do not install an agent automatically.

## Verification and publication

The release pipeline requires security, portable, native, upstream-regression,
minimal-runtime and disposable systemd upgrade gates. Upgrade legs cover
historical alpha.1 and pinned published alpha.5 **and alpha.6** packages, including
compatible rollback and recovery. Each published upgrade report is tied to this
candidate's source and deb SHA256. Only the tagged workflow publishes.

The accepted alpha.6 runtime completed scoped Android import, browsing, network
handover and A/B long-flow revocation acceptance. Its installed 24-hour local
observation completed with **1,373 samples and 138 successful UI/TLS checks**, no
collection failures, restarts or OOM. Fresh matching-key local database restore
and staging ACME webroot renewal passed. Those observations do not establish
continuous loaded traffic for 24 hours or a maximum supported user count.

The stable decision and remaining limits are attached as
`release-acceptance.json`. See `release-tests.json` for this exact tagged CI;
historical alpha.6 results are not silently relabelled as tests of this package.

## Explicit limitations accepted for v0.1.0

The owner authorized publication on 23 October 2026 with these limits:

- **No network-reachability or censorship-resistance guarantee.** Direct access
  can fail in selected networks despite a healthy endpoint. A cover page, hostname
  or port does not establish resistance to filtering. The observed network
  incident does not establish a particular filtering mechanism.
- **No advertised concurrent-client capacity or throughput/loss envelope.**
  Resource sizing remains a planning estimate; sustained capacity and disk-sync
  costs have not been benchmarked on the deployment node.
- **Independent full-stack recovery after host loss is unverified.** Local
  database restore passed; it does not establish recovery of the whole host.
  Preserve a matching key and configuration with every private backup.
- **An actual future public certificate replacement remains unverified.**
  Staging renewal passed without deploying its test certificate or invoking
  the agent's deploy hook; this is not evidence of a later live replacement.
- Client evidence covers the recorded CLI 1.1.7 and Android 17 / app 1.2.0
  scenarios. Broader client/platform interoperability is not asserted.

These limits are documented deferrals, not successful tests. Root/operator trust,
private administration and secret-export handling remain part of the deployment
boundary. See [security](https://github.com/precox/SolarTT-UI/blob/v0.1.0/SECURITY.md).

## Upgrade boundary

Publishing v0.1.0 does not update or disable an existing server. Preserve a
consistent backup, matching key, configuration and build provenance before an
authorized upgrade. The package does not start services automatically. Do not
overwrite current quota usage with an older snapshot or assume an arbitrary
binary downgrade is compatible. No credential reissue or port change is required
by this version.
