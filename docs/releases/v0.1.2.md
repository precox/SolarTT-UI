# SolarTT-UI v0.1.2

This stable release adds permanent user deletion and fixes a concurrency error in
quota refills. On 13 November 2026, the owner requested an additional independent
review followed by stable publication after successful checks. The versioned
[acceptance record](https://github.com/precox/SolarTT-UI/blob/v0.1.2/docs/releases/v0.1.2-acceptance.json)
binds that decision to the tested source, package and verification limits.

## Permanent user deletion

**More user actions → Delete user** opens a confirmation naming the user.
Confirming removes the user, active and revoked device profiles and all quota
periods in one transaction. That user's TLS/TCP/UDP connections are cancelled;
success waits for transport ownership and outstanding byte permits to release.
Other users retain their connections and quota. Audit entries and bounded retry
receipts remain under their normal retention rules. Logical deletion does not
erase existing backups, saved client copies or promise forensic SQLite erasure.

An unknown result retains the original deletion request after refreshing the user
list or signing in again in the same page session, including when the user card
has disappeared. Reloading or closing the page loses that in-memory request. Deleted
users cannot regain quota history through checkpointing, refills, manual period
changes or calendar rollover. Saved deleted-user credentials remain denied after
restart and matching-key local restore of a post-deletion snapshot.

## Concurrent quota refills

Two reservations could both queue a refill against an empty shared pool. Once
the first worker replenished it, the second could incorrectly report a storage
error and terminate an allowed TCP or UDP stream. This error also existed in
v0.1.1. A zero-grant refill now rechecks the current pool. Refill admission also
checks durable counter headroom, so reaching the counter ceiling cannot create
a retry loop. Real quota exhaustion and storage-write failures still deny access.
Deterministic regressions cover concurrent TCP/UDP, the final finite quota grant,
residual counter capacity and waiting for outstanding permits.

## Review and acceptance

The owner confirmed cancellation and permanent deletion in Chrome on the
unchanged panel UI in v0.1.2-alpha.1. Independent Astra review found and reproduced
the refill error, then reviewed the exact correction. Focused policy and UI tests,
the corrected built-package observation and recovery results are recorded in the
[checks summary](https://github.com/precox/SolarTT-UI/blob/v0.1.2/docs/releases/v0.1.2-checks.json).
The stable publisher additionally requires all nine exact-tag CI jobs, all four
upgrade matrix legs and verified public assets.

The original manual A observer timed out before deletion; that segment does not
prove A's transport closure. A later diagnostic also timed out waiting for DoT.
The historical helper could report a timeout after an already-ended H2 stream;
the helper was corrected, but the underlying cause of those past failures is not
established. Separate direct/tunnel TCP and mixed TCP/UDP comparisons passed.
The current fixed-package run is separate evidence and does not rewrite either
earlier failure. The observation is light synthetic QA on a shared host, not a
24-hour or capacity test. Chrome's exact version and the owner's OS were not reported.

## Compatibility and limits

The supported target remains Ubuntu 24.04 x86_64 with systemd. External dependency
versions, database schema, configuration defaults, profile format and the managed
upstream patch are unchanged. The stable upgrade pilot uses the pinned public
v0.1.1 package; alpha.1, alpha.5 and alpha.6 migration paths remain mandatory.

No network-reachability guarantee, concurrent-client count or throughput/UDP-loss
envelope is advertised. Independent full-stack recovery and actual public
certificate replacement remain unverified. ACME staging evidence is historical
v0.1.1 evidence for the unchanged TLS/reload path, not a new v0.1.2 ACME run.
The existing scoped dependency-advisory review and informational warnings remain
visible; this release does not update or suppress those dependencies.

Publication does not install the package over a working VPN or authorize changes
to production identities, keys, proxies or firewall rules. Coordinate any rollout
with its own backup and recovery plan.
