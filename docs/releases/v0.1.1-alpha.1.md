## SQLite security fix

[RUSTSEC-2026-0459](https://rustsec.org/advisories/RUSTSEC-2026-0459.html)
affects SQLite before 3.54.0. Opening a crafted database together with a sibling
WAL file of a different page size can expose uninitialized page-cache bytes.
This release updates Rusqlite 0.32.1 to **0.41.1** and libsqlite3-sys 0.30.1 to
**0.39.1**, bundling **SQLite 3.54.1**. SQLCipher is not enabled.

The backup call uses the newer API. Explicit cache and fallible unsigned-integer
features retain the existing statement-cache and `u64` conversion behavior;
the unused WASM SQLite backend is disabled. The project's Rust 1.95 toolchain
satisfies the dependencies' Rust 1.89/1.88 minimums. No schema conversion is
introduced by the dependency update.

The exact redistribution inventory now contains **296 packages and 544 notice
files**. All four changed crate archives and notice bytes were independently
verified; foldhash's Zlib notice and the MIT/Apache wrapper notices are preserved.
See the [dated dependency review](https://github.com/precox/SolarTT-UI/blob/v0.1.1-alpha.1/docs/dependency-redistribution-review.md#sqlite-security-maintenance-review--2026-11-09).

## Managed policy fixes

- Reject IPv4 multicast destinations in SolarTT's managed adapter, including UDP.
  Normal IPv4 unicast and the existing IPv6/private/own-address restrictions are
  retained. The pinned TrustTunnel managed patch is unchanged.
- Continue monthly rollover for other due users when one user's period creation
  fails. The failed user's history and pending schedule are retained, and an
  error is reported after the pass. Retries and restart must not erase charges
  or multiply a period transition.
- Tighten listener-regression evidence: successful original TCP/UDP roundtrips,
  an elapsed listener deadline and a marked stream-loss assertion are required
  before attributing failure to the previous implementation. Fixture/build
  failures do not count as proof of the bug.

## Verification and limits

The runtime change set passed
[all nine required CI jobs before versioning](https://github.com/precox/SolarTT-UI/actions/runs/42703586826).
The exact tagged source must independently pass the full release workflow before
publication. Attached `release-tests.json` and `build.json` bind those results
and the released packages to the tag's actual source commit.

Automated coverage includes the linked-SQLite security floor, live WAL
backup/restore, transactional migration, multicast admission and UDP accounting,
multi-user rollover retry/restart, pre-fix/fixed H2 and listener proofs, quota and
revoke-A/preserve-B isolation, package lifecycle and minimal runtime. Upgrade,
guarded rollback and restore run on disposable GitHub VMs against historical
alpha.1 and the published alpha.5, alpha.6 and stable v0.1.0 packages. RustSec
informational warnings remain visible; no advisory ignore list is introduced.

These are isolated CI results. Human/field acceptance, sustained observation,
manual restore and ACME staging checks have not been performed for this
candidate. Historical v0.1.0/alpha.6 evidence is not new candidate acceptance.
Capacity, independent full-stack recovery, actual public-certificate replacement
and network reachability retain their documented limitations. No supported
client-count, throughput/loss or censorship-resistance guarantee is made.

## Upgrade boundary

The supported target remains Ubuntu 24.04 x86_64 with systemd. This prerelease
does not change schema, configuration defaults, the control API, device-profile
format or the pinned managed upstream patch. Before a separately authorized
installation, preserve a consistent database backup, its matching key,
configuration and build provenance. Guarded rollback requires a compatible
snapshot and must preserve committed quota usage.

Publication does not install a package, restart VPN, rotate credentials or
authorize a production rollout. Follow the backup/upgrade procedure and arrange
an operational window separately.
