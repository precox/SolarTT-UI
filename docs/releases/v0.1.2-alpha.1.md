# SolarTT-UI 0.1.2-alpha.1

This prerelease adds permanent user deletion on top of published
[v0.1.1](https://github.com/precox/SolarTT-UI/releases/tag/v0.1.1). The stable release
continues to provide the existing block-user and revoke-profile actions.

## Changes

**More user actions → Delete user** opens a named confirmation. Deletion removes
the user, active and revoked profiles, and all quota periods in one transaction.
It cancels that user's TLS/TCP/UDP connections and acknowledges completion after
transport ownership and outstanding byte permits are released. Other users keep
their connections and quota.

Unknown outcomes retain the same request for retry after refresh or sign-in,
including when the user has already disappeared from the list. Manual and
calendar period transitions reject deleted users before writing quota history.
Audit entries and bounded retry receipts retain their normal retention; existing
backups and client copies are outside logical deletion. See
[storage and audit semantics](../storage-and-audit.md#permanent-user-deletion).

## Compatibility and acceptance

The agent advertises the added `delete_user` capability; the panel offers deletion
only when supported. Schema, configuration defaults, dependency versions and the
managed upstream patch are unchanged from v0.1.1.

The stable upgrade pilot uses the exact published v0.1.1 package pinned by source
commit and verified asset hashes. CI also exercises the historical alpha.1,
alpha.5 and alpha.6 upgrade paths, real scoped TCP/UDP cleanup, browser confirmation
and cancellation, failed-write rollback, period-transition races and restart.

On 13 November 2026, the owner confirmed cancellation, permanent deletion of
synthetic A and retention of B in Chrome, then separately requested prerelease
publication. The tested basis is source `f91adebbf11cb648e869750960a935196d2e034c`,
package SHA256 `a96c7701610ad84045ad8c2abe834845f5b15737988ea5c6fe2bcbc7cb04fea4`.
The publication preparation changes documentation only; exact tagged-source CI
and public-asset verification remain required. See the
[publication and acceptance record](https://github.com/precox/SolarTT-UI/blob/v0.1.2-alpha.1/docs/releases/v0.1.2-alpha.1-publication.json).

Checks confirmed removal of A's document and quota ledger, denial of all three
active/revoked credential exports and both saved active profiles, and retention
of one deletion audit event. B completed 612 real TCP/DoT and UDP/DNS pairs over
626.966 seconds on its original transport, with no failures or reconnects.
The original A observer timed out before the manual deletion, so its closure is
not claimed. A separate short deletion of synthetic D verified real TCP/UDP
traffic immediately before deletion and closure of both original TLS transports.
The final stopped backup and matching-key local restore preserved document,
ledger, audit and retry receipts; A remained absent and B remained present.

The test used isolated non-root processes and synthetic state on a shared
Ubuntu 24.04 x86_64 host, not a separate VM or a production package installation.
Chrome's exact version and the owner's OS were not reported. This is scoped
deletion acceptance, not a new sustained-load, capacity or physical-client
compatibility claim. The temporary processes, listeners and secrets were removed.
The prior [v0.1.1 owner decision](../stable-acceptance-2026-11-12.md) remains scoped
to that release. Stable v0.1.1 remains Latest; this prerelease grants no production
installation authorization.
