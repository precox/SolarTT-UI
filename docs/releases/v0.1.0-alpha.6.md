# SolarTT-UI v0.1.0-alpha.6 — candidate

Status: **not published; candidate acceptance pending**, prepared 2026-10-21.
The latest public release remains alpha.5. These notes cover the changes since
that tag; they do not establish acceptance of a new binary or authorize an
installation on an existing node.

## Managed transport fix

The managed HTTP/2 listener could close a transport after waiting 600 seconds
for a new CONNECT even when existing TCP/UDP streams were carrying data.
It now removes completed request tasks and keeps listening while an unfinished
request remains. Empty transports still expire; TCP connection and individual
UDP-flow idle timers remain separate. Quota, expiry and revocation retain their
managed cancellation path. Configuration defaults and the wire protocol do not
change.

An open UDP multiplexer counts as an unfinished CONNECT even without active
destination flows. This fix does not add an idle timeout to that multiplexer.
Existing connection/task limits still apply; this is not a promise that every
transport with no recent payload will close at the listener deadline.

Real TLS/H2 regressions exercise limited and unlimited A/B accounts through
accelerated listener deadlines without new CONNECTs or auxiliary health checks.
Revoking A must close A while B's original TCP/UDP streams survive. Separate
cases cover empty transports and completed health requests. CI reconstructs
the previous implementation, requires failure, restores the exact fixed source
and requires success. See [the fix and test scope](../managed-listener-timeout.md).

## Security maintenance

The locked rustls-webpki dependency advances from 0.103.15 to 0.103.16 for
[RUSTSEC-2026-0382](https://rustsec.org/advisories/RUSTSEC-2026-0382.html).
The update rejects certificate paths containing known distrusted emSign keys.
The package's unchanged ISC notice was checked against both exact crate
archives; the redistribution inventory was updated for this identity.
See [the dependency review](../dependency-redistribution-review.md#security-maintenance-review--2026-10-20).
Installing this candidate is separate from updating the repository lockfile;
existing alpha.5 packages are unchanged.

## Maintenance, CI and documentation

- A weekly stable TrustTunnel watcher creates review tasks; upstream updates
  still require patch porting, review, CI and an operator-controlled rollout.
- Daily RustSec maintenance can propose a narrowly bounded dependency patch PR
  when enabled. It does not merge proposals or install an agent automatically.
  Optional external health and Telegram observers have separate setup steps.
  Their live activation and first scheduled/vulnerability events must be
  verified independently; shipping the scripts is not evidence of delivery.
- Upgrade pilots cover both historical alpha.1 and the published alpha.5
  package, including guarded recovery. A generated manual kit identifies the
  exact candidate and baseline; it does not provision a VM or perform human
  acceptance.
- GitHub Actions pins were updated. README mobile previews use synthetic data.

## Candidate checks and upgrade boundary

The PR #12 source passed seven required CI jobs and independent Sol xhigh
review. The versioned candidate still needs its own complete CI and scoped
[human acceptance](../manual-acceptance.md) before publication authorization.
The alpha.5 Android checks are historical baseline evidence; they do not verify
this candidate's timeout correction. In particular, verify original TCP/UDP
streams for more than 10 minutes without periodic health CONNECT workarounds.
An isolated environment for that human check remains deferred pending an
available, explicitly authorized host.

No database schema change, credential reissue or export-port change is introduced
by this release preparation. Before an authorized upgrade, preserve a consistent
database backup, its matching encryption key, configuration and build provenance.
Follow [backup and upgrade](../backup-upgrade.md); do not reset committed quota
spend or assume that any older binary is a safe rollback. Service restarts and
production installation require their own coordinated window.

This remains an experimental alpha. Production capacity, an actual future ACME
certificate replacement, independent off-host recovery and content-specific
mobile-network behavior are not established by isolated CI or a successful
connection indicator. See [the remaining release gates](../release-gates.md).
