# SolarTT-UI v0.1.0-alpha.4 — initial public alpha

> Replaces withdrawn alpha.3. GitHub-safe filenames and upload-name checks fix
> download/checksum identity; runtime behavior is unchanged.

Independent self-hosted TrustTunnel management for a supervised single-node
pilot. Alpha.1 and alpha.2 were internal development builds. **No stable version
exists yet.** Supported target: Ubuntu 24.04 x86_64, HTTP/2 TCP/UDP.

## Included

- Mobile web panel: users, per-device credentials, manual Android setup fields.
- Admin-set issued-profile limits (0–16); refuse a limit below existing profiles.
- Shared bidirectional payload quotas, expiry, calendar resets and durable usage.
- Individual rotation/revocation; restricted Unix API, encrypted credentials,
  bounded audit/storage, backup and guarded restore.
- Debian package, identical binary tar, reconstructable source archive,
  source/upstream provenance, license notices and SHA-256 checksums.

Keep administration private through SSH forwarding. Package installation creates
accounts/directories but starts no services and changes no firewall, SSH or
existing proxy/VPN configuration. You supply DNS, trusted TLS certificates, a
local cover origin and reviewed proxy integration. One profile per device is
recommended; copied credentials cannot be recognized as different physical devices.

## Verification scope

Release CI runs functional/JavaScript/browser checks, H2 TCP/UDP quota and
revocation isolation, secret/dependency scans and actual Ubuntu systemd package
installation/upgrade/guarded recovery. A separate minimal Ubuntu **container**
checks packaged runtime operation without Rust, compiler, Node or Chromium;
it does not replace systemd VM acceptance. Attached reports record exact results.

## Deferred to stable

Recorded Android versions across Wi-Fi/mobile/network switching, representative
24–72 h capacity/resource observation, operational certificate renewal and
independent off-host restore. No promised users-per-node, physical anti-copy,
HTTP/3, IPv6, payments or multi-node management. Existing operator observations
are bounded evidence and do not establish censorship resistance.

Back up the database and matching encryption key before upgrades. Schema 2 and
explicit profile-limit fields cannot be read by older development binaries;
never downgrade over a live database without the documented guarded procedure.
Checksums detect corruption; the alpha is not a reproducible-build or independent
signature guarantee. See build.json for the exact SolarTT and upstream commits.
