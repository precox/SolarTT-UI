# SolarTT-UI v0.1.1 — patch candidate

This is a prepared candidate, not a published release or completed human
acceptance record. Publication requires the reviewed exact-source CI and a
separate versioned owner decision. Existing v0.1.0 assets and tags stay immutable.

## Fixes

- The managed endpoint rejects IPv4 multicast destinations. The previous adapter
  denied IPv6 and explicit own/blocked addresses but could admit locally scoped
  IPv4 multicast through upstream's destination filter. The fix is in SolarTT's
  adapter; the pinned managed upstream patch is unchanged.
- Monthly rollover processes all due users when one user cannot create a new
  quota period. Failed users retain their history and pending schedule; healthy
  users still receive their independent monthly transition. The call reports
  an error after the pass rather than silently hiding failed transitions.
- Listener regression evidence requires successful original TCP/UDP roundtrips,
  an elapsed listener deadline and a marked stream-loss assertion with fixture
  tasks still running. Unrelated setup or build failures do not prove the bug.

## Compatibility and verification scope

No database schema, configuration defaults, control API, device-profile format,
external dependency versions or managed upstream patch changes. Normal IPv4
unicast forwarding and existing IPv6/private/own-address restrictions remain.
No production profiles or quota history need conversion.

New regressions cover multicast policy admission without multicast traffic,
continued UDP unicast and exact payload accounting, and A-at-period-cap/B-due
rollover across retries and restart. Disposable package upgrades cover published
v0.1.0 in addition to alpha.1, alpha.5 and alpha.6. Exact CI results must be recorded
before release; planned tests in this document are not PASS evidence.

The supported target remains Ubuntu 24.04 x86_64 with systemd. Network reachability,
capacity benchmarks, independent full-stack recovery and actual public-certificate
replacement retain the explicit v0.1.0 verification limits. No new field-acceptance
claim is implied by a code fix or successful CI.
