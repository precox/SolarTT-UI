# SolarTT-UI v0.1.0-alpha.5 — managed download fix

This is an alpha prerelease; publication and operational rollout are separate steps.

## Fixed

Managed HTTP/2 forwarding could stop partway through a response when a durable
traffic-accounting lease split a buffer. The pending quota tail waited for sink
writability before requesting fresh HTTP/2 capacity. It now retries the write
to request capacity; genuine sink backpressure still waits. Both limited and
unlimited users use these leases and were affected. This defect belongs to the
SolarTT managed patch, rather than the unmodified TrustTunnel endpoint.

A real TLS/H2 regression downloads a one-way 1-MiB response across the 256-KiB
lease boundary and checks exact payload accounting for both policy types. CI
first reconstructs the previous behavior and requires the download timeout,
then restores the fix and requires success. Quota and revocation isolation,
legacy upstream, package lifecycle and minimal-runtime gates remain required.

An isolated operator probe with official Linux CLI 1.1.7 also reproduced partial
HTML/JavaScript downloads before the fix, using two DNS resolvers. The fixed
candidate completed all twelve tunneled requests, including a 4.5-MB response;
static resource hashes matched direct downloads. This is bounded server-path
evidence, not Android, mobile-network or censorship-resistance acceptance.

## Upgrade

Back up the database, matching encryption key and build provenance, then stop
the panel and agent cleanly before installation. This correction introduces no
database schema change. Preserve profiles, policies and quota history; no
credential reissue is required. Services are started explicitly by the operator
after installation. Follow [backup and upgrade](../backup-upgrade.md).

After rollout, repeat complete page/resource downloads on the actual Android
client over Wi-Fi and mobile networks. Connected status alone is insufficient.
The 24–72 h observation, network switching, certificate renewal, capacity and
other stable acceptance gates remain outstanding. This is still an alpha.

Android 1.2.0 diagnostic guidance now explains that sensitive-data exclusion
forces native error logging even if application Detailed logging is selected.
Never share raw full logs or working profile secrets publicly.
